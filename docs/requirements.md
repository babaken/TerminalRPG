## 1. 概要

### 1.1 目的
ターミナル上で動作する、ASCII 表現のみの RPG エンジンを Python で開発する。
エンジンとゲームデータ（シナリオ）を分離し、シナリオパッケージ（zip）を差し替えることで別のゲームを遊べるようにする。
あわせて、シナリオ制作用の周辺ツールとマニュアル、サンプルシナリオ「FirstQuest」を提供する。

### 1.2 スコープ
| 区分 | 対象 |
|---|---|
| 本体 | ゲームエンジン（実行環境） |
| ツール | アスキーアート変換ツール / マップエディタ / シナリオパッケージ（圧縮）ツール / シナリオ検証ツール[決定] |
| ドキュメント | シナリオ作成マニュアル / データ仕様書 / 利用者向け README |
| コンテンツ | サンプルシナリオ「FirstQuest」一式 |

### 1.3 スコープ外
- 画像・音声の再生（**[決定]** 音なし・画像なし）
- オンライン／マルチプレイ
- オートセーブ（**[決定]** 無し）
- GUI ウィンドウ（ターミナル専用）

## 2. 用語

| 用語 | 意味 |
|---|---|
| エンジン | 本体プログラム。シナリオパッケージを読み込んで実行する |
| シナリオパッケージ | 1 本のゲームを構成するデータ一式を zip 化したもの（例: `FirstQuest.zip`） |
| シナリオスクリプト | `scenario.sco`。イベント進行・会話・分岐・エフェクトを記述する |
| エフェクト | 画面演出（発光・移動・降下物など）。スクリプトから呼び出す |
| AA | アスキーアート。キャラクター・敵・背景の表現に用いる |
| セル | ターミナル上の 1 文字分の表示領域（全角文字は 2 セル） |

## 3. 動作環境・技術要件

| 項目 | 内容 |
|---|---|
| 言語 | **[決定]** Python（**[決定]** 3.11 以上。`tomllib` 標準搭載のため） |
| OS | **[決定]** Windows 10/11（Windows Terminal）および Linux。macOS はベストエフォート |
| 端末 | **[決定]** UTF-8 / ANSI エスケープ（VT100）対応ターミナル。Windows の旧 conhost は非推奨 |
| 描画方式 | **[決定]** 自前のダブルバッファ描画（差分のみ ANSI 出力）＋ 標準ライブラリ `unicodedata`（East Asian Width）で全角幅計算。曖昧幅文字は既定 1 セル（起動オプションで 2 に切替可）。curses は Windows で全角の扱いが不安定なため不採用 |
| キー入力 | **[v1.1]** Windows: `ReadConsoleInputW` で入力レコードを直接読み、Enter・Esc・矢印などは仮想キーコードで判定 / Linux: `termios`+`tty`。抽象化レイヤで切替。（当初の `msvcrt` は日本語入力が絡むと Enter・Esc を取りこぼすため変更） |
| 外部依存 | 最小限（`cryptography`, `Pillow`〔AA 変換ツールのみ。`pip install .[tools]`〕）。描画・入力は標準ライブラリのみ|
| 配布 | **[決定]** `pip install` 可能な構成＋ Windows 向けに PyInstaller で単体 exe を任意提供 |

### 3.1 画面サイズ
- 原案「最小 800x600」はピクセル指定だが、ターミナルはフォント依存のため **文字数（セル）で定義** する。
- **[決定]** 最小 **100 桁 × 30 行**（一般的な 8x16 フォントでおよそ 800x480〜800x600 相当）
- 最小未満のときは「ウィンドウを広げてください（現在 W×H / 必要 100×30）」を表示して一時停止し、拡大されたら自動復帰する。
- 最小以上では、メッセージ欄・マップ表示範囲・AA 表示領域を広げて活用する（フレキシブルレイアウト）。
- 起動中のリサイズを検知して再レイアウトする。

## 4. 機能要件（ゲームエンジン）

### 4.1 起動・シナリオ読込
- F-01 カレントディレクトリ（および `scenarios/` フォルダ[決定]）の `*.zip` を走査し、有効なシナリオパッケージを列挙する。
- F-02 1 つだけならそのまま読み込む。複数ならタイトル前に選択画面を出す。**[決定]** 起動引数 `--scenario A.zip` で直接指定も可。
- F-03 パッケージ内の `manifest`（後述）の必須ファイル・バージョン互換をチェックし、不備は日本語のエラーメッセージで行番号つきで表示する。
- F-04 開発用に、zip ではなく展開済みフォルダも読み込めるモード（`--dev ./FirstQuest/`）を持つ。[決定]

### 4.2 タイトル画面
- ニューゲーム / ロード / 言語設定 / 終了
- タイトル AA・タイトル名はシナリオパッケージ側で定義する。

### 4.3 フィールド・マップ
- F-10 タイルベースの 2D 見下ろしマップを、主人公を中心にスクロール表示する。
- F-11 マップ種別: 町・村 / フィールド / ダンジョン（階層）。
- F-12 タイルに属性を持つ（通行可否、エンカウント率、イベント起動、ワープ先）。
- F-13 NPC を配置でき、話しかけ・自動起動・接触起動でスクリプトを呼ぶ。
- F-14 ランダムエンカウント（マップ／領域ごとに出現テーブル）。
- F-15 ダンジョンは階層（B1F〜）を持ち、階段で移動する。
- **[決定]** ダンジョンも 2D 見下ろしで統一（マップエディタ共用）

### 4.4 会話・イベント
- F-20 メッセージウィンドウでの会話表示（話者名、1 文字ずつ表示、キーで送り／スキップ）。
- F-21 選択肢表示と分岐。
- F-22 フラグ・変数によるイベント制御（章の進行、仲間の選択結果など）。
- F-23 立ち絵／顔の AA を会話中に表示できる。[決定]

### 4.5 戦闘
- F-30 **[決定]** 複数人パーティ vs 複数敵のターン制。
- F-31 **[決定]** ターン方式: 全員のコマンドを入力 → 素早さ順に実行（ドラクエ型）。
- F-32 コマンド: たたかう / じゅもん・スキル / どうぐ / ぼうぎょ / にげる。
- F-33 敵は AA で表示。複数体を横並びに配置し、狙い先はカーソル選択。
- F-34 状態異常（毒・麻痺・眠り 等）、属性（**[決定]** 火・氷・雷・聖・闇の 5 種）。
- F-35 戦闘結果: 経験値、ゴールド、ドロップアイテム、レベルアップ。
- F-36 イベント戦闘（スクリプトから呼び出し、逃走不可・負けイベント指定可）。
- F-37 テイマー職のための「仲間にする（テイム）」コマンド。**[決定]** 戦闘中に「手なずける」→ 1 体を随伴させる（パーティ枠外、1 体まで）
- F-38 敵 AI: パターン指定（通常攻撃のみ / ランダムスキル / HP 条件で行動変化 / 特定キャラ狙い）。
  - 1 章「主人公だけ狙われる」演出のため、**特定キャラ狙い** を必須とする。

### 4.6 キャラクター・成長
- F-40 パーティ最大人数 **[決定]** 4 人（主人公 + 仲間 3）。
- F-41 ステータス: Lv / HP / MP / 攻撃 / 防御 / 魔力 / 素早さ / 運。
- F-42 職業ごとの成長率・習得スキル表。
- F-43 装備: 武器 / 防具 / 盾 / 装飾品。
- F-44 職業（サンプルシナリオ用）: 勇者（主人公）、戦士、魔法使い、僧侶、遊び人、アマゾネス、テイマー。

### 4.7 アイテム・ショップ・施設
- F-50 アイテム（消費 / 装備 / だいじなもの）。「錆びた剣」「地図」「帰還の巻物」はだいじなもの扱いとし、スクリプトから付与・判定できる。
- F-51 ショップ（売買）、宿屋（回復）。
- F-52 冒険者協会: 依頼（クエスト）の受注・報告・報酬受取。
  - **[決定]** エンジン共通の「クエスト機能」として実装し、クエスト定義はデータ側に置く。
- F-53 仲間募集（酒場相当）: スクリプトから候補を提示し選択させる。

### 4.8 メニュー
- ステータス / どうぐ / そうび / じゅもん / クエスト一覧 / セーブ / 設定（文字送り速度・言語）

### 4.9 セーブ・ロード
- F-60 **[決定]** 手動セーブのみ。オートセーブなし。
- F-61 **[決定]** セーブ可能場所: どこでも可 / 宿屋・セーブポイントのみ をシナリオ側で指定可能。
- F-62 **[決定]** スロット数 3。
- F-63 セーブファイルは暗号化し改ざん検知する（6.2 参照）。
- F-64 セーブデータはシナリオ ID とバージョンに紐づけ、別シナリオのデータは読み込まない。
- F-65 **[決定]** 全滅時の挙動はシナリオで設定:
  - `retry_from_save`（最後のセーブから）/ `title`（タイトルへ）/ `choose`（プレイヤーに選択させる）
  - **[決定]** 戦闘単位・イベント単位で上書き可能（負けイベント用）。

### 4.10 言語
- F-70 **[決定]** 言語切替対応、既定は日本語。
- F-71 エンジンの UI 文言は言語ファイルで管理（`lang/ja.toml`, `lang/en.toml`）。
- F-72 シナリオ本文の多言語化は、パッケージ内に言語別テキストファイルを置けば対応できる仕組みにする。**[決定]** エンジン UI は日英対応、サンプルシナリオ本文は日本語のみ。

## 5. エフェクト（シナリオ演出）

スクリプトから `@effect 名前 引数...` の形で呼び出す。すべて非ブロッキング指定（`wait=false`）も可能とする。

| ID | 名前 | 内容 | 主な使用場面（FirstQuest） |
|---|---|---|---|
| E-01 | `flash` | 画面全体を指定色（白/黒/赤…）で発光、回数・間隔指定 | 剣を拾う瞬間、ボス出現 |
| E-02 | `fade_in` / `fade_out` | 暗転・明転（文字の濃度を段階変化） | 場面転換、就寝 |
| E-03 | `shake` | 画面を横／縦に揺らす | モンスター襲来、ボスの咆哮 |
| E-04 | `move` | 指定オブジェクト（敵・NPC）をセル単位で移動 | 「敵が左に 1 つ移動」 |
| E-05 | `starfall` | 右上から左下へ流れ星が斜めに降る | 旅立ちの夜、エンディング |
| E-06 | `rain` / `snow` | 雨・雪のパーティクル | 村を追い出される場面 |
| E-07 | `typewriter` | 中央に大きく文字を 1 文字ずつ表示 | 章タイトル表示 |
| E-08 | `wipe` | 左右／上下からのワイプ切替 | マップ切替 |
| E-09 | `blink` | 指定オブジェクトを点滅 | ダメージ、宝箱 |
| E-10 | `aa_show` / `aa_hide` | AA を指定位置に表示・消去（スライドイン可） | 回想、ボス登場 |
| E-11 | `scroll_text` | スタッフロール風に下から上へ流す | エンディング |
| E-12 | `tint` | 画面全体の色調変更（セピア・夜・赤） | 回想、夜、危機 |
| E-13 | `wait` | 指定ミリ秒待機 | 間の演出 |

- **[決定]** 色が使えない端末向けに、色指定は無視しても成立する演出にする（モノクロフォールバック）。
- **[決定]** エフェクトはプラグイン形式（Python クラス登録）で追加可能にする。ただし zip 内の Python コード実行は安全上禁止（6.3）。

## 6. 非機能要件

### 6.1 性能
- 描画は差分更新で 30fps 相当（エフェクト時）を目標。通常時はキー入力駆動で再描画。
- シナリオ読込は 2 秒以内（サンプル規模）。

### 6.2 セーブデータの保護
- 原案「暗号化し復号化されないことを想定」について：鍵は配布物のプログラム内に必ず存在するため、**解析されれば理論上は復号可能**。目標を以下のとおり定義する。
  - 一般ユーザーがテキストエディタ等で内容を読めない・書き換えられないこと
  - 改ざんされた場合は確実に検知して読み込みを拒否すること
- **[決定]** 方式: AES-256-GCM（認証付き暗号）。鍵はエンジン埋め込み秘密値＋シナリオ ID から HKDF で導出。形式バージョンをヘッダに持つ。
- **[決定]** 上記の水準とする（完全な解読防止は目標にしない）

### 6.3 安全性
- シナリオパッケージは第三者配布を想定し、**任意コード実行をさせない**（スクリプトは独自 DSL のみ、Python の `eval` 不使用）。
- zip 展開時のパストラバーサル（`../`）、巨大ファイル（zip bomb）をチェックする。

### 6.4 保守性
- エンジン／データ／ツールをパッケージ分割。
- データファイルとスクリプトは UTF-8 テキストで、Git で差分管理できること。
- 単体テスト（pytest）: スクリプトパーサ、戦闘計算、セーブ暗号化、パッケージ検証。

### 6.5 ユーザビリティ
- 操作キー: 矢印 / WASD / テンキーで移動、Enter・Z で決定、Esc・X でキャンセル、M でメニュー。**[決定]** キー割当は設定ファイルで変更可。
- エラー時は Python のトレースバックではなく、原因と対処を日本語で表示（開発モードでは詳細も出す）。

## 7. データ仕様（案）

> **[v1.1]** 現在の正式なデータ仕様は基本設計書 v0.2 の 3〜10 章を参照（本章は v1.0 時点の案）。

### 7.1 シナリオパッケージ構成
```
FirstQuest.zip
├─ manifest.toml       … タイトル、ID、作者、バージョン、対応エンジン版、全滅時設定、初期状態
├─ scenario.sco        … シナリオスクリプト（必須）
├─ Map.data            … 全マップ定義（必須）
├─ Enemy.data          … 敵・敵グループ・出現テーブル（必須）
├─ Friends.data        … 主人公・仲間候補・職業定義（必須）
├─ Items.data          … アイテム・装備・スキル（[決定] 追加）
├─ Quests.data         … クエスト定義（[決定] 追加）
├─ aa/                 … アスキーアート（*.txt、色情報は任意の *.color）
└─ lang/               … 言語別テキスト（任意）
```
- **[決定]** ファイル名 `Enemy.data` / `Map.data` / `Friends.data` / `scenario.sco` は原案どおり。
- **[決定]** `.data` の中身は **TOML 形式**（人が読み書きしやすく、コメント可、Python 標準で読込可）。
- **[決定]** `Items.data`（アイテム・装備・スキル）と `Quests.data` を追加する。

### 7.2 Enemy.data（例）
```toml
[[enemy]]
id = "mole_a"
name = "ハタケモグラ"
aa = "aa/mole.txt"
hp = 40
mp = 0
atk = 12
def = 6
agi = 5
exp = 18
gold = 12
drops = [{ item = "herb", rate = 0.2 }]
ai = "random"
skills = ["dig_attack"]

[[group]]
id = "field_1"
members = ["slime", "slime", "bat"]
```

### 7.3 Map.data（例）
```toml
[[map]]
id = "village_home"
name = "ハジマリ村"
width = 40
height = 20
encounter = "none"
tiles = """
########################################
#....T....~~~~.......H....T...........#
...
"""
[map.legend]
"#" = { name = "wall", pass = false }
"." = { name = "ground", pass = true }
"T" = { name = "tree", pass = false }
"~" = { name = "water", pass = false }
"H" = { name = "house", pass = false }

[[map.npc]]
id = "mother"
char = "@"
x = 21
y = 3
talk = "ch1_mother_talk"   # scenario.sco のラベル
```

### 7.4 scenario.sco（スクリプト構文案）
行指向の独自 DSL。制作者がプログラミング未経験でも書けることを優先する。
```
*ch1_start
@effect typewriter "第1章　出会いと旅立ち"
@bgm none
@map village_home 20 10
カイ「今日は森で探検しようぜ！」
@choice
  - 行く → *ch1_forest
  - やめておく → *ch1_stay

*ch1_forest
@effect fade_out 500
@map forest_1 5 5
@effect fade_in 500
@flag set lost_friend
...
@if flag:found_sword
  @goto *ch1_reunion
@endif

@battle group=village_raid escape=false gameover=title target_only=hero
```
- 主要命令: `*ラベル` / 会話文 / `@choice` / `@goto` / `@call`・`@return` / `@if`〜`@else`〜`@endif` / `@flag` / `@var` / `@map` / `@npc` / `@battle` / `@item` / `@gold` / `@party add|remove` / `@recruit` / `@quest` / `@effect` / `@wait` / `@shop` / `@inn` / `@save_point` / `@chapter` / `@ending`
- 詳細構文は「シナリオ作成マニュアル」で定義する。

## 8. 周辺ツール

| ID | ツール | 要件 |
|---|---|---|

## 10. サンプルシナリオ「FirstQuest」要件

### 10.1 方針
- 原案のプロットを基に、会話・NPC・エフェクトを肉付けして `scenario.sco` 化する。
- **エンジン機能のショーケース** を兼ねる：全エフェクト・全全滅設定・選択分岐・クエスト・仲間選択を一度は使う。

### 10.2 章ごとの要件（原案→必要機能の対応）

| 章 | 主な出来事 | 使用機能 |
|---|---|---|
| 1章 出会いと旅立ち | 森で友達と逸れる→錆びた剣発見→再会→家族団らん→翌日襲撃（主人公だけ狙われる）→村八分→追放→近くの街→門番・町人と会話→冒険者協会登録→クエストで資金稼ぎ→仲間1人選択（戦士/魔法使い/僧侶） | 会話、flash、fade、shake、イベント戦闘（特定キャラ狙い）、rain、クエスト、ショップ、仲間選択 |
| 2章 | 冒険者死亡事件の噂→依頼で村へ→モグラ型モンスター討伐→地図ドロップ→協会へ報告→指名依頼→見張り撃破→ダンジョン B1F〜B10F→B11Fで帰還の巻物→帰還・報告→仲間2人追加（1章で選ばれなかった職＋遊び人/アマゾネス/テイマー） | ドロップによる大事なもの、指名クエスト、階層ダンジョン、アイテムによるワープ、フラグ参照の候補絞り込み |
| 3章 | 深層調査→幹部ガルザに完敗→神殿の試練で強化→三柱の魔の伝承 | 負けイベント（`lose=`）、パーティ一時離脱、tint、試練用ソロ戦闘 |
| 4章 終わりの始まり | 蝕王ヴェルムの名→ガルザ再戦→ヴェルム2段階戦→残る二柱の示唆→帰還・村と和解 | ボス連戦、flash、starfall、scroll_text、ending |

### 10.3 規模目安 [決定]
- プレイ時間 3〜5 時間、マップ 15〜20 枚、敵 30 種程度、ダンジョン B1F〜B11F＋3・4 章分。
