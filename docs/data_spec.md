# データ仕様書（シナリオパッケージ） v1.0

シナリオパッケージを構成するファイルの、すべての項目の仕様です。
エンジンの読み込み処理（`src/trpg/data/loader.py`・`src/trpg/package/manifest.py`）に合わせています。
書き方の入門は [シナリオ作成マニュアル](manual/README.md)、スクリプトは [スクリプトリファレンス](manual/02_script.md) を見てください。

- データ形式版：**1.0**（manifest の `engine` で対応を指定）
- この仕様書に載っていない項目を書くと「未知の項目」の警告になります（綴り間違い対策）。

---

## 0. 共通

### 0.1 パッケージ
| 項目 | 内容 |
|---|---|
| 形式 | フォルダ、またはそれを zip にしたもの（`manifest.toml` が zip の直下か、1 段下のフォルダの直下） |
| 必須ファイル | `manifest.toml` `scenario.sco` `Map.data` `Enemy.data` `Friends.data` |
| 任意ファイル | `Items.data` `Quests.data` `aa/*.txt` `aa/*.color` ほか（`@include` する .sco、スタッフロールのテキストなど） |
| パス | パッケージの直下からの相対パス、区切りは `/`。絶対パス・`..` は使えない |
| 文字コード | UTF-8（BOM なし推奨）。改行は LF / CRLF どちらでもよい |
| 言語別のファイル | `lang/<言語>/` に同じ名前のファイル（`lang/en/scenario.sco` `lang/en/Items.data` など）を置くと、UI がその言語のときは元のファイルの代わりに使う。`manifest.toml` の `languages` の 2 番目以降に書いた言語だけが対象。置かなかったファイルは元のまま（`@include` 先も同じ） |
| 安全 | zip の展開時に、パストラバーサル（`../`）・ファイル数（1 万）・1 ファイル 32 MB・合計 256 MB・異常な圧縮率を拒否。zip 内の Python は実行しない |

### 0.2 .data の書式
- TOML（https://toml.io）。`#` から行末はコメント。
- 同じ種類のものは `[[種類]]`（テーブルの配列）で並べる。中の表は `[[種類.子]]` か `{ … }`（インライン）で書く。
- 書式の誤りは行番号つきのエラーになる。

### 0.3 型の表記
| 表記 | 意味 |
|---|---|
| 文字列 | `"…"` |
| 整数・数値 | `12` / `0.5` |
| 真偽 | `true` / `false` |
| ID | 英小文字で始まり、英小文字・数字・`_` だけ（例 `slime_2`）。種類ごとに重複不可 |
| 文字列の配列 | `["a", "b"]` |
| 整数の組 | `[最小, 最大]` |
| 能力値 | `{ hp = 30, mp = 5, atk = 8, def = 6, mag = 3, agi = 6, luk = 5 }`。書かない能力は 0 |
| 条件式 | `"flag.x and gold >= 100"`（[スクリプトリファレンス 4 章](manual/02_script.md)） |
| 色名 | `black red green yellow blue magenta cyan white gray` と `bright_red` などの `bright_〜` |
| 全角 1 文字 | 表示幅 2 の文字（`＃` `木` など）。曖昧幅の記号（`■` `─` など）は端末でずれるので警告 |

### 0.4 能力値（stats）
| キー | 意味 |
|---|---|
| `hp` | 最大 HP |
| `mp` | 最大 MP（魔法に使う） |
| `atk` | 攻撃（物理ダメージ） |
| `def` | 守備（受ける物理ダメージを減らす） |
| `mag` | 魔力（魔法ダメージ・回復量・魔法への抵抗） |
| `agi` | 素早さ（行動順・回避・逃走） |
| `luk` | 運（会心の一撃） |

## 2. Friends.data

### 2.1 `[[job]]` 職業
| 項目 | 型 | 必須 | 既定 | 説明 |
|---|---|---|---|---|
| `id` | ID | ○ | | |
| `name` | 文字列 | ○ | | 表示名 |
| `growth` | 能力値 | | すべて 0 | レベルアップ時の平均上昇量（実際は ±1 のゆらぎ） |
| `equip` | 文字列の配列 | | `[]` | 装備できるアイテムの `category`。空なら何でも装備できる |
| `skills` | 表の配列 | | `[]` | `{ lv = 3, skill = "power_slash" }`：その Lv で覚えるスキル |
| `sp` | 表 | | なし | 技に使う SP：`{ base = 10, growth = 3, regen = 3 }` |

`sp` の中：
| 項目 | 型 | 既定 | 説明 |
|---|---|---|---|
| `base` | 整数 | `0` | Lv1 の最大 SP |
| `growth` | 整数 | `0` | Lv が 1 上がるごとの最大 SP の増加（最大 SP = base + growth ×（Lv − 1）） |
| `regen` | 整数 | `3` | 戦闘中、毎ターンの終わりに回復する SP |

`skills` の中：`lv`（整数・必須・1 以上）、`skill`（スキル ID・必須）。

## 6. Quests.data

### `[[quest]]` 依頼（冒険者協会）
| 項目 | 型 | 必須 | 既定 | 説明 |
|---|---|---|---|---|
| `id` | ID | ○ | | `quest.ID` `@quest give ID` で使う |
| `name` | 文字列 | ○ | | |
| `goal` | 表 | ○ | | 達成条件（下表） |
| `reward` | 表 | | `{}` | `{ gold = 60, exp = 10, items = ["herb"] }`（経験値は生き残った仲間で等分） |
| `giver` | 文字列 | | `"guild"` | 依頼主（いまは `guild` のみ） |
| `desc` | 文字列 | | `""` | 説明 |
| `rank` | 文字列 | | `""` | 表示用のランク（F〜A など） |
| `repeatable` | 真偽 | | `false` | 何度でも受けられる |
| `when` | 条件式 | | `""` | 掲示板に出る条件 |
| `on_complete` | ラベル | | `""` | 報告のあとに実行するラベル |
| `random` | 真偽 | | `false` | ランダムの依頼。下の「ランダムの依頼」を参照 |

`goal` の中：
| 項目 | 説明 |
|---|---|
| `type` | `deliver`（納品）`defeat`（討伐）`reach`（そのマップに入る）`flag`（フラグが立つ） |
| `item` | `deliver` のアイテム ID |
| `group` | `defeat` の敵グループ ID か敵 ID（グループなら 1 戦 1 回、敵 ID なら倒した数） |
| `map` | `reach` のマップ ID |
| `flag` | `flag` のフラグ名 |
| `count` | 数（既定 1） |


#### ランダムの依頼（`random = true`）
- 掲示板には、いつもの依頼のあとに、ランダムの依頼が manifest の `random_quests` 個（既定 3）まで貼られる。
- 受けた依頼や条件（`when`）を満たさなくなった依頼は外れ、掲示板を開くたびに残りの候補から補充される（受けきっても、別の依頼が出てくる）。
- 補充するとき、受けられる候補のうちいちばん `rank`（F→E→D→C→B→A→S）の高いものが掲示板になければ、まずそれを 1 つ貼る。エリアごとに `when` とランクを上げていけば、新しいエリアの依頼が必ず 1 つ出る。
- 達成しても何度でも受けられる（`repeatable` は不要）。貼ってある依頼はセーブに残る。

## 7. AA ファイル（aa/）

### 7.1 `*.txt`
- 1 行目が `;;` で始まればメタ行として読み飛ばす。
- 半角空白は、戦闘画面・マップの上では透明（下が見える）。顔・タイトルは透明にしない。
- 全角文字は 2 桁ぶん。

### 7.2 `*.color`（任意）
- `aa/slime.txt` の色は `aa/slime.color`。AA と同じ行・同じ文字の位置に 1 文字ずつ色コードを書く。
- `k r g y b m c w`（黒 赤 緑 黄 青 紫 水 白）、大文字で明るい色、`.` か空白で既定の色。足りない部分は既定の色。
- 検証：対応する AA のない色ファイル（警告）、使えない色コード（エラー）、AA より長い行（警告）。
- 画像から作るなら `python -m trpg.tools.aa_convert 画像 --color`。

## 9. セーブデータ（参考）

シナリオ作成者が書くものではありませんが、互換性のために仕様を示します。

| 項目 | 内容 |
|---|---|
| 場所 | `<セーブフォルダ>/<package.id>/slot1.sav`〜`slot3.sav`（セーブフォルダは環境変数 `TRPG_SAVE_DIR`、なければ起動フォルダの `saves/`） |
| 暗号 | AES-256-GCM。鍵は package.id から導く。改ざん・別シナリオのセーブは読まない |
| 中身 | パーティ（Lv・能力・装備・状態異常・覚えたスキル・SP）・所持金・所持品・フラグ・変数・依頼・章・位置・一度きりのイベント・NPC の状態・継続エフェクト・プレイ時間・ペット・書き換えたタイル・一時離脱中の仲間・罠の配置 |
| 互換 | 項目が足りない古いセーブも読める（既定値で補う）。シナリオの version が変わっても読める |

シナリオを更新して、すでに通り過ぎた場面に処理を足したときは、`*on_load` で古いセーブを補正します（[よくある作り方](manual/04_recipes.md)）。

## 10. 検証（--check）

`python -m trpg --check パッケージ` は、上の型・必須・選択肢・範囲・ID の重複・未知の項目に加えて、次を確かめます。

- ID の参照（職業・装備・スキル・状態異常・敵・グループ・出現表・マップ・タイルセット・ショップの品物・依頼の目標と報酬・罠・使い魔）
- 装備欄と slot の不一致、最大 SP が 0 の職業の SP スキル
- AA ファイルの欠落、マップの行の長さ、タイルセットにない記号、文字の表示幅
- マップの外の座標（エラー）、通れないタイルの上の NPC・ワープ先（警告）、NPC の道順
- スクリプトの全項目（[スクリプトリファレンス 9 章](manual/02_script.md)）
